# Coffee Exhibition Project

مرجع اصلی مدیریت پروژه نمایشگاه قهوه علی کافه.

## هدف
ثبت و مدیریت یکپارچه استراتژی، برنامه‌ریزی، فروش، بازاریابی، غرفه، لیدها، عملیات، KPIها و تصمیم‌های پروژه.

## وضعیت فعلی
- کسب‌وکار: علی کافه
- تمرکز محصولات: دان سبز، دان رست‌شده، پودریجات، برندهای دیگر و تجهیزات قهوه
- پنج لاین پرفروش: مستر، توربو، بلک توربو، بالانس، انرژی
- مشتریان اصلی فعلی: کافه‌ها
- جهت توسعه: فروش B2B و توسعه کانال پخش

## ساختار پروژه
- `PROJECT_BRIEF.md` — خلاصه و مبنای پروژه
- `strategy/` — اهداف، مشتریان هدف و استراتژی فروش
- `planning/` — نقشه راه، زمان‌بندی، بودجه و چک‌لیست
- `booth/` — مفهوم و طراحی غرفه و برندینگ
- `sales/` — فرآیند فروش و اسکریپت‌ها
- `marketing/` — برنامه قبل، حین و بعد نمایشگاه
- `leads/` — مدیریت لید و پیگیری
- `operations/` — نیرو، برنامه روزانه و لجستیک
- `reporting/` — KPI و گزارش‌دهی
- `decisions/` — ثبت تصمیم‌های کلیدی
- `management/` — داده‌های اصلی مدیریت پروژه در قالب CSV

## اصل داده و مدیریت
**CSV منبع اصلی داده‌های مدیریتی پروژه است.**

اطلاعات ساختاریافته پروژه باید در CSVهای `management/` ثبت و نسخه‌بندی شود. Excel یا Google Sheets در صورت استفاده، لایه مدیریت، تحلیل و نمایش هستند و نباید به‌عنوان منبع مستقل و متعارض با CSV عمل کنند.

هنگام تغییر داده‌های مدیریتی:
1. ابتدا CSV مربوطه به‌روزرسانی شود.
2. تغییر مهم با Commit معنادار در Git ثبت شود.
3. در صورت وجود فایل مدیریتی Excel/Google Sheets، اطلاعات مرتبط با CSV سینک شود.
4. اگر بین CSV و فایل مدیریتی اختلاف وجود داشت، قبل از overwrite اختلاف بررسی شود.
5. پس از هر Freeze، اطلاعات مرتبط با نسخه فریز‌شده سینک شود.

ساختار فعلی پروژه بدون دلیل مدیریتی مشخص تغییر نکند و تصمیمات مهم، تغییرات محدوده، بودجه یا زمان‌بندی اصلی بدون تأیید مدیر پروژه قطعی نشوند.

## استانداردها
- Branch اصلی: `main`
- Repository باید Private بماند.
- تاریخ‌های CSV با فرمت `YYYY-MM-DD` ثبت شوند.
- شناسه‌های مدیریتی استاندارد حفظ شوند؛ از جمله `T-001` برای Task، `M-001` برای Milestone، `R-001` برای Risk، `REQ-001` برای Requirement، `D-001` برای Decision و `S-001` برای Stakeholder.
- وضعیت‌ها باید استاندارد و ثابت بمانند تا گزارش‌ها و داشبوردها دچار خطا نشوند.

## امنیت
اطلاعات محرمانه، رمزها، کلیدهای احراز هویت، Token، Secret و اطلاعات حساس مشتریان نباید در این repository قرار بگیرند.

هر چیزی که در داده‌های پروژه مشخص نشده باشد نباید حدس زده شود؛ اطلاعات ناقص باید با داده واقعی تکمیل شوند.
